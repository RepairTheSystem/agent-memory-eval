# Эксперименты и воспроизводимость

## Что сохранено

`results/historical/` содержит четыре компактных экспорта авторских запусков.
Для каждого сохранены модель, набор, число успешных ответов, исходные метрики,
булевы вердикты по отдельным кейсам и SHA-256 исходного отчёта.
Тексты ответов, исходные диалоги внешних наборов и внутренние журналы не публикуются.
Хеш фиксирует происхождение экспорта, но не заменяет доступ к исходному отчёту.

`python scripts/verify_results.py` независимо пересчитывает доли, 95% интервалы Вилсона
и точный парный тест Макнемара по сохранённым вердиктам. Это проверка арифметики
публикуемых результатов. Она не повторяет генерацию и не проверяет решения LLM-судьи.

## Собственные сценарии

Исторический набор `scenarios/benchmark_255.json` содержит 255 синтетических сценариев:
248 оцениваемых и 7 демонстрационных. Поддерживаются категории извлечения, обновления,
временных зависимостей, отказов при отсутствии сведений, границ пользователей и организаций,
забывания, переполнения контекста и другие проверки.

Расширенный `extended_302.json` — отдельная версия набора. Исторические проценты в README
получены не на нём. Нельзя объединять количество сценариев новой версии с метриками старой.

Собственный набор использовался в ходе разработки и подбора архитектуры. Его результат
показывает покрытие заданных сценариев и не является независимой оценкой обобщения.

## Протокол исторических запусков

- По одному повтору на наборе для каждой модели. Многократная оценка стабильности
  этих исторических цифр не выполнена.
- Основная первая модель: `qwen/qwen3-next-80b-a3b-instruct`.
- Вторая модель: `qwen/qwen3.8-27b`.
- Сравнение `before` и `search`: одна исходная архитектура и новая профильная схема.
- Исходный результат собственного набора для первой модели взят из более раннего
  запуска; новые варианты получены после доработок эмулятора. Это не единый
  одновременно проведённый прогон двух замороженных реализаций.
- Модель-судья совпадает с моделью агента. На собственном наборе также применяются
  проверки по эталонным условиям сценария.
- Полные параметры каждого запроса и все тексты ответов в публичном экспорте отсутствуют.

Поэтому повторение команд воспроизводит методику, но не гарантирует совпадение каждой цифры.
Для нового строгого сравнения следует зафиксировать версии модели и кода, запустить оба
варианта вместе с тремя или более повторами и использовать отдельную модель-судью.

## LongMemEval

Использован **oracle**-вариант: 500 вопросов с отобранными сессиями, содержащими
нужные сведения. Это более узкая постановка, чем поиск по полной длинной истории.
Сравнение относится только к выбранной исходной схеме; превосходство над другими
системами памяти или опубликованными результатами полного LongMemEval не заявляется.

Второй модели исходная схема на 147 из 500 вопросов вернула пустой ответ из-за ограничения
на число вызовов функции памяти. Часть прироста связана с исправлением пути выполнения,
а не только с качеством хранения фактов. Этот эффект включён в опубликованные доли.

## Как повторить

1. Запустить локальные проверки и холостой прогон из README.
2. Подготовить личный ключ OpenRouter в игнорируемом файле `openrouter.env`.
3. Запустить небольшой пилот. Затем сравнить `before` и `search` на одном наборе.
4. Для публичной проверки отдельно получить LongMemEval oracle у авторов набора.
5. Сохранить отчёты нового запуска, модель, параметры, дату и идентификатор версии кода.

Проверка стенда с `fake` не является экспериментом по качеству модели.
Новый прогон через API оплачивается владельцем его ключа.
