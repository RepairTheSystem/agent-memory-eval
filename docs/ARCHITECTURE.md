# Архитектура Python-прототипа

## Два уровня сравнения

`MemorySystem` в `pipeline.py` моделирует исходную цепочку «сбор → аннотирование →
классификация → чтение → ответ». Переключатели `Fixes` позволяют менять отдельные
механизмы, а не сравнивать только две непрозрачные реализации.

`ProfileSystem` в `profile.py` использует те же часы, диалоги, модели и сценарии,
но хранит структурированный профиль. Постоянное хранение здесь моделируется
словарями и списками; после завершения процесса состояние не сохраняется.

## Профиль

Профиль разделён на личные сведения, предпочтения, текущие дела и организации.
Строки имеют идентификатор, дату, возможный срок действия и предыдущее значение.
Отдельно хранятся архив, журнал принятых/отклонённых операций и позиция обработки диалога.

Модель предлагает `add`, `replace`, `remove`, `merge`, `archive` и `add_org`.
Код проверяет операции по отдельности. Для обычной правки требуется цитата из диалога;
для замены — прежнее значение строки; для удаления — явная просьба забыть этот факт.
При сжатии проверяется сохранение числовых значений. Отклонённая операция не должна
повреждать другие строки. Нечёткое совпадение цитат и проверка чисел остаются эвристиками.

## Сессии и чтение

Сессия разбирается после паузы (по умолчанию 30 минут в моделируемом времени).
До разбора агент может получить недавние реплики других диалогов с пометкой об их статусе.
Контекст чтения ограничен приблизительным бюджетом 1500 токенов. При переполнении
строки могут быть скрыты из вида, объединены или перемещены в архив.

Вариант `search` добавляет BM25-поиск по архиву и скрытым строкам.
`remember` / `forget` дают возможность немедленной обработки явных команд.

## Ограничения реализации

- Это симулятор логики, не сервер памяти и не промышленная система хранения.
- Замки и транзакционные ситуации исходной схемы моделируются в Python.
- Бюджет контекста рассчитывается по символам, без токенизатора модели.
- Промпты и бизнес-ориентированная таксономия сохранены ради сопоставимости экспериментов.
- Фильтры чувствительных данных и цитат не гарантируют отсутствие ошибок LLM.

Экспериментальные флаги не следует автоматически считать готовыми политиками для
продуктовой системы: для внедрения нужны отдельные требования и проверки.
