# Agent Memory Eval

**Долговременная память LLM-агента: проверяемое обновление профиля, ограниченный контекст и поиск по архиву.**

Автор: [Олег Шутько / RepairTheSystem](https://github.com/RepairTheSystem).

Исследовательский Python-прототип и стенд для сравнения архитектур памяти. Проект проверяет,
как агент сохраняет факты между диалогами, исправляет устаревшие сведения, выполняет команды
«запомни» и «забудь» и извлекает сведения, которые не поместились в текущий контекст.

## Задача и решение

Исходная схема собирает отдельные факты, аннотирует их, назначает темы и читает память через
вызов функции. Ошибка выбора темы, потерянное уточнение или необработанный факт могут
сделать сохранённую информацию недоступной агенту.

В новой схеме используется структурированный профиль пользователя:

1. После завершения сессии модель предлагает изменения с цитатами-основаниями.
2. Python-код проверяет адресуемую строку, прежнее значение, наличие цитаты,
   границы организации и допустимость операции. Решения записываются в журнал.
3. Агент получает ограниченный по размеру вид профиля и недавние ещё не обработанные реплики.
4. При переполнении модель предлагает слияние и архивирование. Проверки отклоняют
   операции сжатия, теряющие числовые значения.
5. `remember` / `forget` обрабатывают явные команды, а `search_memory` ищет по архиву
   и скрытым строкам с помощью BM25.

Бюджет основного вида — приблизительно 1500 токенов; здесь токены оцениваются по числу
символов. Это ограничение контекста LLM, а не лимит оперативной памяти процесса.

## Быстрый запуск без ключей и сети

Нужен **Python 3.10 или новее**. Сторонние Python-библиотеки не требуются.
Выполняйте команды из корня репозитория. В Windows вместо `python` можно использовать `py`.

```bash
python -m unittest discover -s tests -v
python scripts/verify_results.py
python scripts/check_release.py
python run.py mock
python run.py live --provider fake --only IE KU CMD --variants before search --out smoke
```

Отчёты появятся в `reports/`: откройте `mock.html` или `smoke.html` в браузере.
`fake` — детерминированная тестовая модель. Её показатели проверяют работу стенда,
а не качество настоящей языковой модели.

## Исторические результаты

Один сохранённый прогон на каждом наборе и каждой модели; сравнение с исходной схемой `before`.

| Модель | Набор | Исходная схема | Профиль + архивный поиск |
|---|---|---:|---:|
| Qwen3-Next-80B-A3B-Instruct | Собственные сценарии, 248 оцениваемых | 121/248 (48,8%) | 232/248 (93,5%) |
| Qwen3-Next-80B-A3B-Instruct | LongMemEval **oracle**, 500 вопросов | 128/500 (25,6%) | 316/500 (63,2%) |
| Qwen3.8-27B | Собственные сценарии, 248 оцениваемых | 120/248 (48,4%) | 224/248 (90,3%) |
| Qwen3.8-27B | LongMemEval **oracle**, 500 вопросов | 142/500 (28,4%) | 295/500 (59,0%) |

В первом прогоне на собственном наборе число вызовов модели на сообщение уменьшилось
с 3,12 до 1,61. Учёт вызовов охватывает все 255 сценариев, включая 7 демонстрационных;
точность считается только по 248 оцениваемым.

Скрипт `verify_results.py` заново вычисляет доли, доверительные интервалы и парный тест
Макнемара из опубликованных вердиктов. Он не обращается к моделям и не проверяет правильность
самих вердиктов. Ответы моделей и журналы внутренних запусков в этот выпуск не включены.

**Границы сравнения:** собственный набор использовался при разработке; это не независимый
отложенный тест. `before` — конкретная исходная схема, а не лучшая известная система памяти.
LongMemEval oracle уже содержит сессии с нужной информацией: эти числа нельзя напрямую
сравнивать с результатами на полном LongMemEval. Модель-судья совпадала с моделью агента.
Подробности и известные ограничения: [EXPERIMENTS.md](docs/EXPERIMENTS.md).

## Повторение экспериментов с настоящей моделью

Этот режим отправляет синтетические диалоги выбранному API и расходует средства его аккаунта.
В опубликованном проекте нет ключей: нужен собственный ключ OpenRouter.

1. Скопируйте `openrouter.env.example` в `openrouter.env`.
2. Локально заполните `OPENROUTER_API_KEY`. Файл исключён из Git.
3. Проверьте небольшой набор, затем запускайте полный.

```bash
python run.py ping --provider openrouter
python run.py live --provider openrouter --only IE KU --variants before search --out pilot
python run.py live --provider openrouter --variants before search --repeats 3 --workers 4 --out repeated
```

Названия моделей и доступность у провайдеров могут меняться. Для сравнения фиксируйте
модель, дату, параметры, набор, число повторов и версию кода.

Публичные наборы загружаются отдельно из [LongMemEval](https://github.com/xiaowu0162/LongMemEval)
или [LoCoMo](https://github.com/snap-research/locomo) с соблюдением их условий. Положите файл
в локальную папку `datasets/`, например `datasets/longmemeval_oracle.json`.

```bash
python run.py public --data datasets/longmemeval_oracle.json --provider fake --groups 2 --max-questions 2 --variants before search --out public-smoke
python run.py public --data datasets/longmemeval_oracle.json --provider openrouter --variants before search --workers 4 --out longmemeval
```

## Варианты архитектуры

| Вариант | Что проверяется |
|---|---|
| `before` | Исходная схема: сбор, аннотирование, классификация по темам, вызов функции чтения |
| `after` | Локальные исправления исходной схемы |
| `nofilter` | Исправления и чтение фактов без выбора тем |
| `lite` | Факты в системном контексте и недавние реплики |
| `ctx` | Сбор фактов с известным контекстом |
| `profile` | Профиль-документ, разбор сессии и проверка правок |
| `full` | Профиль, сжатие, архив и команды `remember` / `forget` |
| `search` | Дополнительно `search_memory` по архиву и скрытым строкам |
